# 要件定義 — StampRallyBot（仮称）

## 1. 概要

建物内（最大15部屋）で同時開催されている複数の催しを会場に見立て、参加者がLINE Botの指示に従って各部屋を巡り、部屋担当スタッフからQRコードを提示してもらってスキャンすることでスタンプを集めるスタンプラリー。

各部屋では別々の催し（セッション・展示等）が進行しており、スタンプラリー担当のスタッフが部屋ごとにQRコードを保持・提示する。QRの提示タイミングはスタッフの目視判断に委ねるため、システム側の不正対策は最小限でよい。

スタンプラリーとしては1イベントのみの運用を想定（MysteryBotのようなマルチテナント運用は対象外）。

---

## 2. ターゲットユーザー

| ユーザー | 説明 |
|:--|:--|
| **管理者（イベント運営者）** | スタンプラリー全体を管理する運営担当者。部屋の登録、QRコードの発行、各種設定、ランキング確認を行う |
| **プレイヤー（参加者）** | LINEを使ってスタンプラリーに参加する参加者。個人戦・チーム戦いずれの場合も、代表者1名がLINEアカウントでBotを操作する |

---

## 3. 機能要件

### 管理者機能

- **イベント設定**
  - 個人戦 / チーム戦の切替（イベント単位）
  - 判定モードの切替（イベント単位）：「QR読み取りのみ」⇔「QR読み取り＋LINE上での正解入力」
- **部屋（チェックポイント）管理（CRUD）**
  - 部屋名、クエスト文（プレイヤーに提示する指示文）、画像（任意）を登録
  - 判定モードが「QR＋正解入力」の場合のみ、正解・ヒントも登録
  - 最大15部屋
- **QRコード発行**
  - 部屋ごとにQRコードを自動生成し、管理画面で表示（スタッフが印刷または現地の端末に表示して持ち歩くため）
- **ランキング確認**
  - クリアタイム順のリアルタイムランキング表示（未クリアの参加者は圏外表示）

### プレイヤー機能（LINE Bot / LIFF）

- **ゲーム開始**：「開始」コマンドで参加登録
  - 個人戦：個人名を入力
  - チーム戦：チーム名を入力（メンバー全員は代表者のLINEアカウントに帯同する想定。複数アカウントでの合流機能は不要）
- **部屋の指示**
  - 参加登録直後、および各部屋クリア後に、未訪問の部屋からランダムに1部屋を選出して通知
  - 通知メッセージにはクエスト文・画像を含める（Flex Message）。LIFF（QRスキャンページ）を起動するボタンも含め、参加者がメッセージから直接QRスキャンに進めるようにする
- **クエスト達成・チェックイン**
  - 判定モード「QRのみ」：LIFFでQRコードをスキャンするだけでその部屋をクリア扱いにする
  - 判定モード「QR＋正解入力」：LINEトークで正解を送信して正誤判定 → 正解後にQRスキャンでクリア確定
  - QRスキャン後、LIFFページに「LINEチャットに戻る」ボタンを表示し、参加者が次に何をすべきか迷わないようにする
- **ゴール**
  - 15部屋目のQRを読んだ時点でクリアタイムを記録
  - 「最初の部屋（スタート地点）に戻ってください」と案内（システム的な追加処理はなし、案内のみ）。クリアタイムを含む専用のFlex Messageで演出する
- **ヒント機能**：「ヒント」コマンドで現在の部屋のヒントを表示（判定モードが「QR＋正解入力」の場合）
- **遊び方ガイド**：「遊び方」「ヘルプ」コマンドで操作ガイドを表示
- **リセット**：「リセット」コマンドで自分の参加データを削除

## 4. 非機能要件

| 項目 | 要件 |
|:--|:--|
| 対象規模 | 1建物・最大15部屋・1イベントのみの運用（将来複数イベントに拡張する可能性は考慮するが、今回のスコープ外） |
| セキュリティ | Argon2によるパスワードハッシュ、CSRF保護、IDOR対策 |
| QR不正対策 | システムでは対策しない。QRは部屋担当スタッフが目視確認の上で提示する運用でカバーする |
| 可用性 | Koyebの無料枠でホスティング。無料枠は最小インスタンス数を0に固定できず、アイドル時にインスタンス数0へスケールダウンしうる（常時起動は保証されない）。プロセス再起動をまたいで維持すべき状態（参加登録の一時状態）はDBに永続化し、再起動による実害を避ける（詳細は[architecture.md 18節](architecture.md#18-デプロイ構成koyeb)・[architecture.md 9節](architecture.md#9-会話状態管理参加登録の一時状態)） |
| データ保存 | 画像はDBに保存、UUIDで公開URL生成（MysteryBotの方式を踏襲） |

## 5. MysteryBotからの主な変更点

| 項目 | MysteryBot | StampRallyBot |
|:--|:--|:--|
| ゲームの単位 | 謎（テキスト問題）を順番に解く | 物理的な「部屋」をランダムな順で巡る |
| 正誤判定 | 常にLINE上でテキスト回答必須 | イベット単位で「QRのみ」/「QR＋正解入力」を切替可能 |
| 出題順 | 順番固定 or ランダム（事前決定） | 常に動的ランダム（QR読み取りの都度、未訪問部屋から抽選） |
| マルチテナント | 複数イベントを同時運用 | 1イベントのみ運用 |
| 景品・演出 | ランキングのみ | ランキングのみ（変更なし） |
